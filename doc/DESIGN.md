# JSI 제품 디자인 규칙

batt의 로그인, 생산·품질·연구, 화면 설명, DOCS와 인쇄에 적용한다. 별도 디자인 시스템 페이지를 만들지 않고 실제 업무 화면에서 공통 규칙을 사용한다.

## 현재 정보 구조

상단의 생산·품질·연구가 업무 모드다. 모드 안에서 작업을 선택하고 같은 작업대로 돌아온다. 예전 사이드 메뉴·현장/관제 두 모드·6개 상시 메뉴 구조는 현재 화면 구조가 아니다. 모드 전환은 권한을 부여하지 않는다.

| 모드 | 작업과 판단 근거 | 다음 행동 |
| --- | --- | --- |
| 생산 | 셀 검사·재고, 측정값·출처·결측, 8셀 조합과 SOP 편차 | 조합 검토·팩 구성, 해당 팩 검사 |
| 품질 | 검사·조치 이력, 초도·최신 검사 결과, 독립 승인 근거 | 재검사·검토 요청·승인 또는 반려 |
| 연구: 공정 설계·시뮬레이션 | 장비·작업 순서와 확보 데이터 계획, 입력 시간 기반 효율 추정 | 기준안 비교, 저장·공정 승인 요청 |
| 연구: 데이터·AI 검증 | 현장 판단 학습·8셀 조합 / 수명·안전성 연구 준비 | 비교 근거 보관 / 문헌·스키마와 고객 데이터 준비 비교 |

관리자는 가입·담당 공정·독립 승인권을 설정한다. 조합 확정과 최종 품질 승인은 별개다. 현재 운영 엔진은 SOP·편차 기반이며 학습 모델, 불량 확률, 팩 수명·안전성 예측을 제공하지 않는다.

## 공통 시각 규칙

- 색·글꼴·타입·간격·모서리·테두리·그림자·컨트롤 크기는 src/design-tokens.css에서 정의한다. 컴포넌트는 역할 토큰을 참조하고 같은 의미의 별도 수치를 만들지 않는다.
- 본문·입력·보조문·제목·지표는 type 역할 토큰, 간격은 공통 space 척도, 모서리는 small/control/panel/dialog/pill을 사용한다.
- 매뉴얼은 기존 따뜻한 중립색·청회색을 중앙 manual 의미 토큰으로 유지한다. 매뉴얼 범위에서 공통 색 역할에 매핑하되 타이포·간격·컨트롤 규칙을 공유한다. 상태와 출처 색도 각각 의미를 보존한다.
- 고정 JSX style 객체는 사용하지 않는다. 실행 중 계산하는 좌표·진행률 등은 CSS 사용자 속성으로 전달한다. 차트·Three.js가 계산하는 기하값과 캔버스 크기는 일반 UI 고정 스타일과 구분한다.
- 버튼·입력·선택·표·탭·상태·포커스·비활성 상태는 공통 규칙을 사용한다. 색만으로 상태를 전달하지 않고 텍스트와 근거를 함께 표시한다.

### 공통 척도

| 역할 | 토큰·값 |
| --- | --- |
| 제목 / 구역 / 소제목 | type-title 30px / section 17px / subheading 15px |
| 본문 / 읽기 본문 | type-body 14px / reading 16px |
| 입력·버튼 / 보조 설명 | type-control 13px / caption 12px |
| 지표 / 큰 통계 / 표시 제목 | type-metric 43px / stat 34px / display 52px |
| 줄높이 | body 1.5 / reading 1.65 / control 1.4 / heading 1.25 |
| 간격 | space 1·2·4·6·8·12·16·20·24·32·40·48·64px |
| 모서리 | small 4px / control 6px / panel 10px / dialog 12px / pill 999px |
| 컨트롤 높이 | 기본 44px / compact 32px |
| 테두리 | 기본 1px / 강조 2px |

표의 이름은 src/design-tokens.css의 역할 토큰을 줄여 쓴 것이다. 11px micro는 차트 눈금 등 제한된 데이터 표시에 사용하고 일반 설명문을 작게 만드는 대안으로 쓰지 않는다. 기존 로고의 7px 문양 글자, Three.js 공간 기하, 미디어쿼리 분기점과 인쇄용 물리 치수는 제품 본문 척도와 구분해 보존한다.

## 작업 흐름과 공간

필요한 근거와 다음 행동을 같은 작업 맥락에 둔다. 상세 내용을 접거나 패널을 나누더라도 편집·삭제·되돌리기·목록 복귀가 보이고 접근 가능해야 한다. 제목과 요약을 반복해 작업 영역을 줄이지 않는다.

짧은 화면에서는 안내와 본문이 함께 스크롤되도록 전환해 본문의 최소 작업 높이를 확보한다. 고정 안내가 남은 높이를 모두 차지하거나 부모의 숨김 영역이 마지막 입력·행동을 잘라서는 안 된다. 마지막 행까지 스크롤한 뒤 실제 화면 안에 보이고 다른 요소에 가리지 않으며 클릭할 수 있는지 확인한다.

공정 설계의 장비 편집 / 작업 순서 / 장비 추가는 같은 위치에서 전환한다. 장비 선택과 입력을 유지하고 삭제 후 되돌리기를 제공한다. 공정도와 확보 데이터의 역할을 구분한다. 시간 시뮬레이션은 완료시간·대기·병목 후보를 추정하며 장비 통신 검수나 합성 품질 판정이 아니다. 승인된 계획은 신규 팩의 공정 버전에 반영되고 기존 팩은 생성 당시 버전을 유지한다.

연구 테마 1은 데이터 분포·결측·판정 연결·학습 준비 → 비교 조건 → 후보 편차와 구성 8셀 → 운영 적용 검토를 제공한다. 전체 알고리즘 표는 상세 비교로 펼친다. 좁은 태블릿 화면은 분석 근거와 입력·선택 상세를 같은 위치에서 전환한다. 테마 2는 연구 문헌·스키마 등록과 고객 CSV 준비 비교이며 공개 연구 소개가 주 작업을 가리지 않는다.

데이터 없음은 0% 성과가 아니다. 팩 검사와 셀 판단을 구분하며 재검사 건수를 독립 팩 수로 세지 않는다. 최신 불량률 감소를 알고리즘의 인과적 효과로 표시하지 않는다. 합성·시험·보완·실측 출처를 보존한다.

## 화면 설명·DOCS·검증

화면 설명은 현재 대상만 강조하며 입력을 저장하거나 업무를 대신 수행하지 않는다. 닫기와 업무 복귀를 유지한다. DOCS는 같은 시나리오의 절차·번호가 붙은 실제 UI 캡처·결과·예외를 제공한다. 캡처는 로컬 합성 자료로 생성하고 고객 원본이나 운영 기록을 포함하지 않는다. 인쇄는 모든 이미지를 준비한 뒤 수행하며 실패나 닫기를 처리한다.

공통 CSS 변경은 빌드·단위 검사와 전체 브라우저 회귀 대상으로 취급한다. 지원 대상은 데스크톱과 태블릿이며 스마트폰은 지원하지 않는다. 태블릿 거치 방향을 가정하지 않고 768×1024·1024×768, 800×1280·1280×800, 834×1194·1194×834에서 가로 넘침, 겹침, 컨트롤 접근, 상세 진입·복귀를 검증한다. 960px 이하 작업대는 상세 전환을 사용하고, 표는 뷰포트가 아닌 실제 패널 너비에 맞춘다. 터치 환경의 조작 높이는 44px 이상으로 유지한다. 회전과 키보드로 인한 가용 높이 감소 시 선택한 팩과 저장 전 입력을 유지한다. 기존 320/390px 검사는 확대·작은 창의 퇴행 방지이며 스마트폰 지원을 의미하지 않는다. DOM에 내용이 존재한다는 검사만으로 보이는 작업 흐름을 검증했다고 주장하지 않는다. 최종 UI 이후 매뉴얼 이미지를 재생성하고 DOCS 화면·인쇄 결과를 확인한다. 브라우저 크기·터치 에뮬레이션과 실제 태블릿·OS 검증은 구분해 보고한다.


2026-10-18 진입·연구 레이아웃 기준
- 타이틀은 이미지 높이와 여백을 화면에 맞춰 배분한다. PC와 태블릿 로그인 화면에서 진입 버튼에 접근할 수 있도록 한다. 매우 낮은 화면·확대·긴 오류 안내는 조작을 가리지 않고 필요한 스크롤을 허용한다.
- 공개 체험과 일반 로그인은 생산 작업을 먼저 표시한다. 빈 재고에서는 측정 파일 등록 시작으로 이어진다. 로그인 후 선택한 비공개 고객 데이터 체험은 선택한 데이터 검토 맥락을 유지한다.
- 연구 공정 설계·시뮬레이션의 모드 전환과 공정 승인함은 생산·품질과 같은 작업 제목 줄에 배치한다. 중복된 본문 메뉴 줄과 상시 설명 줄을 두지 않는다. PC는 공정도와 편집부가 같은 높이를 공유하고 긴 편집부만 스크롤한다.


연구 분석의 빈 상태에서도 단계별 판단 질문, 측정 축 또는 근거 연결 흐름, 자료 대기 표시를 제공한다. 빈 그래프에 임의의 값·성능을 넣지 않는다. 분석과 입력 영역을 명시하고 입력 바로가기와 탭 복귀 시 스크롤 초기화를 제공한다. 문헌 선택에서는 대상·요구 스키마·추가 수집 판단을 함께 표시한다.


안내 문구는 사용자의 다음 행동을 먼저 설명하고 필요한 조건을 뒤에 붙인다. 짧은 안내는 한두 문장으로 쓰고 같은 화면의 반복 설명은 줄인다. 조합 기준 충족·검사 합격·최종 품질 승인을 구분하며, 실측/시험 출처·원본 보존·승인 범위·연구 미구현 기능은 생략하지 않는다. 오류 안내는 원인과 다음 행동을 함께 적는다.
