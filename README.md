# JSI Battery Workbench

주성산업 사내 배터리 셀 매칭·품질이력 관리 MVP.

## 현장 기준 반영 (2026-10-16)

현재 목표는 **어떤 셀 8개를 조합할지 추천하고 기준을 통과하는 팩 수를 최대한 늘리는 것**입니다. 업체는 Cell Grading AO열 Cutoff Cap(방전용량)을 중심으로 편성합니다. 이 현행 업무의 타당성 평가는 이번 구현과 별개입니다.

- 사용자 확인 기준: 용량 차 ≤500mAh, 초기 OCV 차 ≤10mV. SOP v2에서 내부저항은 선택 참고값이며 NULL을 보존합니다. v1 기록은 변경하지 않습니다.
- 최대 5가지 탐색 편성을 비교해 통과 팩 수를 우선하고, 같은 수이면 정규화 편차 합을 비교합니다. 탐색 전역 최적성을 보장하지 않습니다. 실제 제공 128행 중 검토 가능 124셀에서 15팩을 확인했습니다. 이 자료의 수량 상한도 floor(124/8)=15팩입니다.
- 고객 자료 검토의 **현장 기준**에서 8개 셀 채널, 용량·OCV 차, 평균·최소 용량, 미배정 셀을 확인하고 근거 JSON을 내보냅니다. 기본은 500mAh이며 회의 언급 50/100mAh는 추가 비교 조건입니다.
- 현장 업무는 셀 충방전 검사 → 용량별 분류·보관 → 8셀 조합 → 모듈 검사 → 케이싱 → 최종검사 순서입니다. 신규 팩은 모듈 검사 합격 후 케이싱 완료, 이후 최종검사를 기록합니다. 상위 공정을 재기록하면 하위 확인을 다시 받아야 합니다. 기존 팩의 에이징·최종검사 기록은 보존합니다. 공정 공간은 회의록의 흐름을 나타낸 개념 배치이며 실제 설비 좌표는 아닙니다.
- 수명과 안정성은 대표가 추가로 알고 싶은 정보이며 장기 AI 추론 목표입니다. 현재 추천 점수는 수명·안정성 점수가 아닙니다. 이후 셀 ID·팩 ID로 모듈/출하검사, 반복 충방전, 온도·부하·사용조건, 고장/교체 이력을 연결하고 현장 검증한 모델을 별도로 적용합니다.
- 원본 Excel/회의록은 변경하거나 공개 저장소에 포함하지 않았습니다. 실제 셀 식별자·LOT·측정 시각의 시간대는 여전히 확인해야 합니다.

배포 순서: `202610160001_field_sop_v2.sql` → `analyze-batch`와 `match-cells` → 웹앱. 구 SOP 실행은 재계산해야 새 팩으로 확정할 수 있습니다. 아래 과거 구현 기록의 0.01mΩ 필수 기준은 v1 이력 설명이며 현재 기준은 이 절을 따릅니다.

## 생산·품질·연구 업무 구성

- **생산**: 공유 3D 현장의 6단계 공정을 선택해 셀 검사·재고, 8셀 조합과 팩 검사를 옆 업무 패널에서 수행합니다. 생산·품질 전환 시 공정·팩·카메라가 유지됩니다. 좁은 화면은 공정 아래에 업무를 배치하고 입력 중에는 업무에 집중합니다.
- **품질**: 품질 현황, 검사·조치 이력, 품질 승인, 분석·보고. 불합격·미연결·검사 대기 지표에서 대상 팩을 추적하고 별도 승인권자가 제출 근거를 검토합니다.
- **연구**: 연구 개요, 공정 설계·시뮬레이션, 데이터·AI 검증. 현행 조합 추천의 목표와 향후 수명·안정성 추론을 구분하며 가상 설계는 실제 공정 기록에 자동 반영하지 않습니다.

설계 연결 방향: 연구의 공정 설계·시뮬레이션에서 현장 공정 모델을 편집하고, 검토·확정한 배치를 생산·품질이 공유합니다. 초안 편집·가상 실행과 운영 배치 적용은 구분합니다. 현재는 회의록 기준 공정 배치를 표시하며, 연구 확정본을 운영 배치로 적용하는 연결은 후속 구현 항목입니다.

상단의 업무 구분과 선택 상태는 세 영역에서 유지됩니다. 하단은 권한 관리·체험·로그아웃만 제공합니다. 모바일에서는 긴 업무 내용을 내부에서 스크롤하며 상단 이동 메뉴를 유지합니다. 셀 검색과 팩 검색은 독립적입니다.

## 운영 구조

- 웹: React / TypeScript / Vite → GitHub Pages (`/batt/`)
- 인증·DB: Supabase Auth / PostgreSQL + RLS
- 매칭: Supabase Edge Function (`match-cells`), TypeScript
- 추가 Python 서버, Docker, GPU는 필요하지 않습니다.

## 구현 범위

가입 신청 → 관리자 승인, 작업자/조회자 역할, CSV/XLSX 표준 양식 업로드,
SOP 기반 8셀 추천, 원자적 팩 승인과 셀 중복 사용 방지, 모듈 검사/케이싱/최종검사 기록,
공정 관제 대시보드, 팩 추적, 텍스트 품질 리포트, 합성 데이터 체험.

비밀번호나 서버 비밀키는 저장소에 포함하지 않습니다. 프런트의 Supabase publishable key는 공개 클라이언트 식별자입니다. 데이터 보안은 RLS 및 인증·승인 검증에 의해 적용됩니다.

## 개발 및 배포

Node.js 24 이상:

```sh
npm ci
npm run dev
npm test
npm run build
```

GitHub Pages는 Settings → Pages → Source를 GitHub Actions로 설정합니다.
main 브랜치 push 시 테스트·빌드 후 배포합니다.

```sh
npx supabase login
npx supabase link --project-ref asfrsorbzmqhnwnxlxar
npx supabase db push
npx supabase functions deploy match-cells --use-api
```

`supabase/migrations`를 순서대로 적용합니다. `tests/security.sql`은 ROLLBACK하는 DB 권한 통합 테스트입니다.
초기 관리자는 신뢰된 관리자 세션에서 Auth 사용자를 만들고 해당 profiles 행의 role='admin', status='approved'를 설정합니다. 이메일이나 가입 metadata만으로 자동 관리자 승격하지 않습니다.

이 MVP는 이메일 발송 없이 가입 신청을 접수하고 관리자가 사내 구성원 여부를 확인해 승인하는 방식입니다. Auth 계정 생성/로그인만으로 업무 데이터에 접근할 수 없습니다. 운영 단계에서 SMTP와 이메일 소유 확인을 추가할 수 있습니다.

## 데이터 양식

### 실제 수행 범위 보완 (2026-10-15)

셀 데이터의 **고객 자료 검토**에서 장비 원자료를 등록합니다. 기존 표준 양식 업로드는 호환 기능으로 유지합니다.

- Cell Grading 88열·2단 헤더를 인식하며 D열 OCV(mV), AO열 방전용량(mAh)을 매핑합니다. 없는 내부저항은 NULL로 보존합니다.
- 파일 SHA-256, 원행·헤더, 매핑 버전, 출처(실측/재구성/합성), 측정 조건을 배치로 기록합니다. 원본 바이너리는 업로드하지 않으며 고객 원본 보관 위치를 유지합니다.
- 바코드 누락 시 파일 해시·채널 기반 임시 ID를 부여합니다. 이것은 물리 셀의 영구 식별자나 파일 간 동일 셀 검증을 대체하지 않습니다. 장비 시간대는 추정하지 않습니다.
- 원자료 배치에서는 결측값을 허용하지만, 팩 재고에는 완전한 측정값만 이관합니다. 내부저항 누락 조합은 전체 SOP 미검증이며 팩 확정할 수 없습니다.
- 동일 적격 집합의 순차 조합과 추천 편성, 최대 3개 대안, 사용·잔여 셀, IQR 1.5배 이상 신호 포함/제외를 비교합니다. 이상 신호는 불량 판정이 아닙니다.
- 셀·8셀 조합의 보류/재검사와 재측정 사유를 저장합니다. 최초 자료는 불변이며 새 검토 버전은 이전 추천 확정을 막습니다.
- 추천은 Edge Function에서 실행하고 입력 스냅샷·조건·SOP·엔진 버전·처리시간·결과를 DB에 보관합니다. 팩에는 추천 실행을 연결하며 DB가 SOP·권한·셀 중복 사용을 다시 검증합니다.
- 검사 입력에서 실측/시험을 선택합니다. 기존 자료는 출처 미확인으로 유지하며 시험/재구성 자료의 승인을 실생산 검증으로 표현하지 않습니다.
- 로그인한 업무 담당자의 연구 모드 결과는 `research_runs`에 저장합니다. 체험 기록은 브라우저 저장이며 연구 결과는 운영 추천으로 자동 승격하지 않습니다.

새 DB 구성은 `202610150001_evidence_workflow.sql`과 `202610150002_consume_batch_cells.sql`, 함수는 `analyze-batch`와 갱신된 `match-cells`입니다. **DB → 두 함수 → 웹앱** 순서로 반영합니다. 새 UI를 DB보다 먼저 배포하지 않습니다. 팩 확정 시 원자료의 해당 셀도 사용 완료로 전환되어 이후 비교에서 제외됩니다.

```sh
npm test
npm run test:db
npm run build
npm run test:e2e
```

`test:db`는 메모리 PostgreSQL(PGlite)에서 마이그레이션·RLS·업무 함수와 미검증/중복/자기 승인 차단을 시험합니다. Auth 신원만 시험용으로 구성하며 Supabase 네트워크·동시 세션 시험을 대체하지 않습니다. 고객 원본은 테스트 저장소에 포함하지 않습니다. 로컬 원본 재검증은 `node scripts/verify-customer.mjs <CellGrading.xlsx> <PoC.xlsx>`로 수행합니다. PoC의 기록된 조합 산술을 검증하며 K-means 실행 재현을 주장하지 않습니다.

학습형 불량·수명 모델 및 실효성 있는 생산현장 실증은 후속 고도화 범위입니다. 현재 검수 대상은 실증 준비형 업무 소프트웨어의 계산·저장·상태 변경입니다. Linux IDC의 Docker 이관 패키지는 별도 후속 작업입니다.

첫 시트/CSV 헤더: `id,lot,voltage_mv,resistance_mohm,capacity_mah,measured_at`.
전압 mV/용량 mAh는 소수 3자리, 내부저항 mΩ는 소수 5자리까지 지원합니다.
measured_at은 `2026-10-14T09:00:00+09:00` 같은 시간대 포함 ISO 문자열입니다.
파일당 5MB / 5,000행. 매칭 요청은 500셀 / 10팩까지입니다.
표준 재고 업로드의 중복 ID는 덮어쓰지 않고 전체 업로드를 거절합니다. 원자료 배치 등록은 위 별도 경로를 사용합니다.

## 해석과 한계

- 매칭은 여러 정렬 순서의 greedy 탐색이며 전역 최적해, 최대 생산 팩 수를 보장하지 않습니다. 추천이 없다는 것은 불가능 판정이 아닙니다.
- 승인 시 DB가 정확한 numeric 값으로 SOP(10mV / 0.01mΩ / 500mAh)를 재검증하고 셀 행을 잠급니다.
- ML 기반 불량 확률, 수명 예측, 보증등급, 자연어 LLM 보고서는 아직 구현하지 않았습니다.
- 대시보드는 등록 데이터의 현재 스냅샷입니다. 센서 실시간 상태가 아닙니다. 로그인한 사용자 추천은 서버 실행·저장되며 체험 추천은 브라우저에서만 실행됩니다.
- 불량률은 팩별 최신 최종검사 결과 기준으로, 초도 불량률과 다릅니다. 미검사 상태는 0%로 표시하지 않습니다.
- 공정 연결률 분모는 전체 등록 팩이며, 신규 팩은 8개 셀 + 모듈 검사 + 케이싱 + 최종검사 연결을 요구합니다. 기존 팩은 에이징 + 최종검사 기준을 유지합니다.
- 초기 검증은 합성 데이터로 진행합니다. 실제 원본 생산데이터의 클라우드 운영 허용 범위는 사업 요구사항에 따라 별도로 확정해야 합니다.
- 팩에 사용된 재고의 측정값·검사이력은 불변입니다. 미사용 재고는 버전 확인과 변경 전후 이력을 남기며 재측정할 수 있습니다. 원자료 배치는 재측정 전후 이력을 보존합니다. 이미 팩에 사용된 셀의 재작업·재사용은 후속 범위입니다.
- 브라우저 체험 데이터는 새로고침하면 초기화됩니다. 실제 사용자 데이터와 혼합하지 않습니다.

알고리즘 검증 모드: 메뉴의 **알고리즘 검증**에서 UConn 전처리 자료 기반 55셀 표본을 불러온 뒤 비교를 실행합니다. 출처·재현 방법·평가 한계·운영 이관 범위는 [RESEARCH.md](doc/RESEARCH.md)를 참고하세요. 조합 비교에는 UConn 55셀을 제공하고, 별도 Severson 열화 이력에는 공식 방전용량 요약 140개 시험 기록(고유 셀 135개, 이어 측정 5개)을 제공합니다. Severson 요약을 조합 엔진이나 수명 예측에 사용하지 않습니다. 연구 결과는 권한에 따라 서버에 저장하지만 운영 SOP·생산 재고·품질 지표는 변경하지 않습니다.

가상 디지털 트윈: 메뉴의 **가상 디지털 트윈**에서 장비 블록을 격자에 배치·회전·연결하고, 태그를 정의한 뒤 가상 작업 흐름과 센서 경보를 관제합니다. 개인 공정 JSON 저장·가져오기와 관제 스냅샷 내보내기를 제공합니다. 실제 장비는 미연결이며 모든 수치는 합성 데이터입니다. 장비 참고 자료·데이터 계약·실제 IoT 연결 후속 범위는 [DIGITAL_TWIN.md](doc/DIGITAL_TWIN.md)를 참고하세요.

다중 사용자 승인: **품질·공정 승인함**에서 실제 팩 품질과 가상 공정 제출본을 검토합니다. 별도로 지정된 품질 승인권자가 승인·반려하며 자기 승인·중복 처리를 서버에서 막습니다. 새 검사 입력은 이전 팩 승인을 재검토 필요로 전환합니다. 관리자는 사용자 관리에서 작업자에게 품질 승인 권한을 부여할 수 있습니다. 공유 편집 없이 제출본과 이력을 보관하며 [APPROVALS.md](doc/APPROVALS.md)에 절차·권한·검증 범위를 정리했습니다.


## Gap 보완 및 검수 (2026-10-15)

- 핵심 구조와 변경 규칙: [ARCHITECTURE.txt](doc/ARCHITECTURE.txt). 인증은 `App`, 화면 조립은 `Workbench`, 생산 명령·조회 수명·보고서는 `application`, DB 접근은 `data` 계층으로 분리합니다.
- 업무 조회는 `read_workbench`의 동일 시점 스냅샷을 사용합니다. 변경 없는 폴링은 이력 전체를 재전송하지 않습니다. 최초/변경 후 전체 스냅샷을 읽는 한계는 남아 있습니다.
- 계정 전환은 작업 공간을 새로 생성하고 이전 조회를 취소합니다. 공개 접속 환경은 `.env.example` 또는 `runtime-config.js`에서 설정하며 배포 순서는 `doc/OPERATIONS.txt`를 따릅니다.

- 마이그레이션 `202610150003_close_review_gaps.sql`은 구형 직접 등록/팩 확정/무버전 검토 API를 비공개로 전환합니다. 새 웹과 두 Edge 함수를 함께 배포해야 합니다.
- 표준 파일 등록도 원행·LOT를 보존한 검토 배치를 생성합니다. 재고의 **측정 검토** 또는 조합의 **보류·재검사 검토로**에서 원자료 배치별 검토로 이동합니다. 기존 출처 미확인 재고의 출처를 임의로 바꾸지 않습니다.
- 표준 엔진 v2/배치 엔진 v3는 LOT별로 편성합니다. 배치 엔진은 완전 측정 후보를 우선 탐색하며 LOT별 IQR이 0이어도 이탈값을 검토 신호로 표시합니다. LOT 미확인 자료의 현장 적합성은 미검증이며 재측정 뒤 과거 추천 확정은 거절됩니다.
- 관제 기본 지표는 실측 팩·실측 검사입니다. 체험은 합성 팩·시험 검사입니다. 선택한 집계 범위를 보고서·품질 비교·대상 팩 조회까지 유지하며 범위와 분모를 명시합니다. 전체·혼합은 참고 집계입니다.
- 마이그레이션 `202610150004_review_decision_context.sql`은 원자료별 재고 검토, 입력 자료형 검증, 처리자 이름 기록, 품질 제출 당시 조합·재검사 근거 고정을 추가합니다. 과거 제출본을 소급 수정하지 않으며 관리자 감사 로그 권한은 확대하지 않습니다. `analyze-batch`와 웹을 함께 배포합니다.
- 배치 이름, 셀/LOT, 이력 셀/시작일 검색과 10건 단위 서버 페이지 조회를 제공합니다. 처리자와 변경 전후 근거를 조회할 수 있습니다. 내보내기는 현재 조회 페이지로 제한된다는 점을 명시합니다.
- `npm run test:db`: API 우회 차단, 원자료 보존, 표준 등록 연계, 재측정 충돌, 과거 추천 무효화, 승인, 격리 DB 아카이브 복원 검증.
- `node --experimental-strip-types scripts/benchmark-evidence.mjs`: 128/500행 재현성, 로컬 wall/CPU 시간. Edge 응답의 elapsed_ms와 CPU 시간을 혼동하지 않습니다.
- `node scripts/test-evidence-backend.mjs`: 합성 시험 계정으로 실배포 Edge, 동시 버전 충돌, 500행 계산, 승인 흐름을 검증하고 시험 자료·계정을 정리합니다. 고객 자료는 사용하지 않습니다.
- 운영 백업/복구 및 미검증 항목은 `doc/OPERATIONS.txt`, 요구사항별 검수 근거는 `doc/ACCEPTANCE.txt`를 확인합니다. 로컬 복원 시험은 실제 Supabase 프로젝트 복원 시험을 대체하지 않습니다.

현장 공정 권한은 기존 담당 범위를 유지합니다. 모듈 검사는 중간검사(`aging`) 담당, 케이싱은 조립(`assembly`) 담당, 최종검사는 `final` 담당이 기록하며 독립 승인자가 최종 품질을 승인합니다.

### 기능 시연 진입 경로
- `가상 데이터로 전체 공정 체험`: 빈 재고 → 가상 충방전 측정값 CSV 다운로드·가져오기 → 검증·등록 → LOT·용량 순 재고 검토 → 8셀 조합 → 모듈 검사 → 케이싱 → 최종검사 → 품질 검토·승인.
- 용량 누락 파일은 등록 오류 시연용이며 자동 보완하지 않습니다. 파일은 장비 실행 결과가 아닌 시연용 표준 측정 양식입니다. 시연 LOT는 현장 분류 임계값을 정의하지 않습니다.
- `등록된 가상 셀로 빠른 체험`: 기존 128개 가상 셀에서 바로 시작합니다. 공개 체험 등록·팩·검사는 시험 자료로 유지하며 서버에 저장하지 않습니다.
- 주성산업 제공 실측 자료는 로그인 후 `고객 데이터 체험` 경로를 유지합니다.
