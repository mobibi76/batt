상세 사용자 매뉴얼 검수 및 유지관리 (2026-10-16)

범위
- 기존 13개 업무 시나리오 전부: 가입/현장/셀 등록/매칭/검사/팩 이력/승인/지표/인입/공정 설계/연구 검증/권한/샘플 체험.
- 실제 앱의 로컬 브라우저 화면 44장(최초 43장에서 후속 개선 시 1장 추가). 캡처 안에 번호·강조선·합성 예시 표식을 넣고 번호별 조작, 입력 예시, 처리 후 확인, 진행·보류 조건, 예외 대응을 제공한다.
- 현장 검사: 팩 선택 → 구분·판정 → 메모·저장 → 불합격 상태 → 실제 재검사 후 두 검사 완료 → 독립 품질 요청.
- 셀 결측: 결측 보존 배치 등록 → 전체 SOP 미검증 → 팩 구성 비활성 → 재검사 근거 보완 안내.
- 고객 자료와 운영 계정은 캡처에 사용하지 않는다. 관리자/비공개 체험 UI는 가상 계정 및 합성 자료의 로컬 API 응답으로 재현한다. 화면의 제공값 표기도 가상 값임을 캡처와 설명에 명시한다.
- 설명용 화면은 정적 예시다. 현재 생산 데이터·실증 성과·실시간 관제 화면이 아니다.

구조
- src/manual/content.ts: 짧은 화면 설명과 공통 담당자/시작 조건/판단 기준.
- src/manual/guidance.ts: DOCS 전용 진입 위치와 상황별 예외 대응.
- src/manual/ManualArticle.tsx: 상세 문서·캡처·번호 목록·결과·인쇄 공통 렌더러.
- src/manual/walkthroughs.json: 캡처 도구가 생성한 시나리오별 이미지·조작 설명. 직접 수정하지 않고 도구 원본에서 변경한다.
- scripts/capture-manual.mts: 실제 조작 시퀀스와 상세 설명 원본. 외부 요청은 차단하고 필요한 가상 API만 로컬에서 응답한다.
- public/manual/screens: 배포에 포함되는 실제 합성 화면 JPEG. 외부 이미지 링크에 의존하지 않는다.
- 모든 앱 스타일은 manual.css와 공통 디자인 토큰을 사용한다. 캡처용 번호 장식은 도구에서만 적용되며 제품 UI를 변경하지 않는다.

다시 생성하기
1. npm run build
2. npm run preview -- --port 4173 (별도 터미널)
3. npm run capture:manual
   특정 묶음: npm run capture:manual -- work (access/work/twin/research/members/sample)
4. 캡처 결과와 설명의 일치 여부를 시각적으로 검수한다. 변경된 화면·버튼·권한 정책이 있으면 해당 묶음을 다시 생성한다.
5. npm run build 후 npm run test:e2e -- tests/manual.spec.ts
6. 변경된 JPEG와 walkthroughs.json을 함께 커밋한다. 공개 파일에 실제 고객값이나 사용자 계정이 포함되지 않았는지 다시 확인한다.

검증
- 13개 시나리오 모두 2장 이상, 실제 이미지 디코딩·번호별 목록·결과·예외 영역 확인.
- 검사 시나리오의 5개 화면, 큰 이미지 새 탭, 단계 이동, 320/390/1366px 가로 넘침과 닫기 버튼 접근성 확인.
- 기존 화면 설명의 입력·선택 보존, 가상 공정 화면 크기 전환, 로그인·공개 DOCS 직접 링크 검사를 유지한다.
- 인쇄 전에 전체 캡처 디코딩을 기다린다. 누락 이미지가 있으면 불완전한 인쇄 대신 재시도 안내를 표시한다.
- 브라우저의 인쇄·PDF 저장은 전체 13개 시나리오를 포함한다. 업무 데이터 화면은 인쇄 대상에서 제외한다.
- 현장 적용 전 교육 담당자가 회사의 실제 SOP·계정 승인 절차·검사 기록 규칙과 문구를 대조해야 한다.
- 추가 검증: 인쇄 준비 중 DOCS를 닫으면 대기 중 인쇄를 취소하여 업무 화면이 대신 출력되지 않는다.
- 검수 결과: 단위 60개, 전체 브라우저 70개 통과 후 인쇄 취소 보완을 포함한 매뉴얼 9개 검사 재통과.

화면 안내 하이라이트 재검수 (2026-10-16)
- 대상 후보를 DOM 순서가 아닌 지정한 우선순위로 선택한다. 업무 모달이 열려 있으면 해당 모달 안에서만 찾는다.
- 검사 근거·검사 구분·판정을 함께 강조하고 메모·저장 영역도 함께 표시한다.
- 승인 새로고침이 검토 근거로 잡히는 문제를 제거하고, 공정 담당/승인권 및 샘플 출처 버튼을 구체적으로 지정했다.
- viewport와 스크롤 부모에 의해 잘린 부분을 제외한다. 닫힌/숨겨진 영역은 강조하지 않으며 현재 화면에 없는 항목은 안내문으로 구분한다.
- 도움말이 열린 동안 위치·크기 변경을 추적한다. 설명창은 겹침이 적은 위치를 선택하고, 불가피한 겹침은 ‘강조 영역만 보기’로 설명을 접을 수 있다.
- 재현: 빌드와 로컬 preview 실행 후 node --experimental-strip-types scripts/capture-manual.mts --audit-help
  기존 합성 캡처용 43개 업무 상태에서 안내 항목을 1366×900, 1366×768, 390×844, 320×480 크기로 각각 클릭한다.
  결과는 .local/manual-help-audit.json에 보관한다. --audit-help는 공개 캡처·문서 내용을 갱신하지 않는다.
  비공개 체험·관리자 화면은 로컬 합성 응답이며 실제 운영 자료/권한 변경은 없다.
- 회귀 검사: 샘플 복귀 버튼과 강조 테두리 좌표 일치, 화면 크기 변경, 승인 도구 오강조 방지, 검사 3개 입력 영역 포함, 강조 영역 접기/복원.
- 재검수 결과: 43개 상태·4개 화면 크기에서 안내 버튼 536건 확인, 전체 브라우저 73개·단위 60개 통과.
UX 개선 후 매뉴얼 갱신 (2026-10-16)
- 검사 판정·근거 명시 선택, 통합 검사 편집기, 승인 근거/판단 분리, 연구 목적별 탐색에 맞춰 설명과 캡처를 갱신했다.
- 현재 13개 시나리오, 44개 합성 화면이다. 비교 결과 표와 보고서 내려받기를 별도 화면으로 설명한다.
- 단위 61개, 전체 브라우저 76개 검사 통과. 캡처 로드·인쇄와 입력 보존을 포함한다.
- 화면 안내는 44개 상태에서 548회 확인해 강조 위치·화면 전환·입력 보존을 재검증했다.

현재 화면 기준 재정리 (2026-10-18)
- 사용 안내와 DOCS의 공통 문구를 현재 메뉴·검사 순서에 맞춘다. 이전 날짜의 검수 수치는 당시 이력이다.
- 연구는 왼쪽 분석 근거·오른쪽 설정, 자료 없는 상태, 모바일 전환과 최근 실험 재개를 설명한다.
- 장비 편집·삭제·작업 순서 복귀를 명시하고 UConn 현재 용량과 Severson 총 사이클 수명의 목적을 구분한다.
- 공개 캡처는 로컬 합성 자료로 전체 재생성한다. 고객 원자료나 운영 계정은 사용하지 않는다.
- 전체 13개 시나리오·55장 재생성 완료. 캡처 전 알림 닫기로 이전 작업의 저장 알림이 다른 업무 화면에 남지 않도록 보완했다.
- 매뉴얼 회귀 12건 통과: 검색·직접 링크·인쇄 준비/취소·이미지 디코딩·입력 보존·320/390/1366px 복귀 및 레이아웃.
