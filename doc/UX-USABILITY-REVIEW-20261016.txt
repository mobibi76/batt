주성산업 batt UX/UI 전문가 관점 업무 시뮬레이션 리뷰
검토일: 2026-10-16 / 코드 기준: 7db3d3e

1. 판단과 범위
현재 화면은 기능이 연결된 실증 준비형 MVP이지만, 현장 반복 작업과 관제의 빠른 품질 판단에 충분히 최적화됐다고 보기는 어렵다.
현장 검사 전용 화면은 비교적 단순하다. 셀 매칭의 결과 검토, 관제 승인, 연구·공정 설계에서 탐색과 문맥 유지 부담이 커진다.
기능 자동검사 통과는 사용성 검증 통과를 뜻하지 않는다. 이번 검토는 도메인 전문가 역할을 가정한 인지적 업무 점검이며 실제 직원 대상 사용성 실험이나 작업 시간 실측은 아니다.
기준은 작업 범위.txt의 실제 수행 범위다. 학습 모델·현장 실증·실장비 관제 완성은 요구하지 않는다. 등록→검증→조합 검토→팩 구성→검사→독립 승인→이력이라는 현재 업무를 잘 수행할 수 있는지 평가했다.

2. 실행 방법
- 기존 실제 UI를 합성 자료로 조작하는 43개 상태를 1366×768 및 390×844에서 관찰했다.
- 가입, 등록, 결측 검토, 조합, 검사·재검사, 승인, 지표·보고, 연구, 설계, 권한, 샘플 흐름을 실행했다.
- 체험 역할 UI의 영향을 분리하기 위해 승인권자 계정을 로컬 응답으로 별도 재현했다. 고객 원본·운영 계정·실제 서버 쓰기는 사용하지 않았다.
- 화면 캡처, 스크롤 컨테이너 크기, 화면 간 이동과 소스의 상태 초기값을 대조했다.
- 1개 팩 중심의 합성 흐름이다. 대량 작업, 교대, 실제 장갑 터치, 현장 조도, 스캐너, 실제 통신 지연은 실사용 검증이 필요하다. 그 부분은 관찰과 구조상 위험을 구별했다.
- 자동화 조작은 위치를 알고 수행하므로, 성공했다는 사실로 처음 사용하는 사람의 발견 가능성이나 이해 속도를 입증하지 않는다.

3. 현장 담당자의 사고 흐름
질문: 지금 손에 든 팩이 무엇인지, 내가 할 검사가 무엇인지, 무엇이 미완료인지, 저장했는지 알고 싶다.
좋은 점: 팩 번호와 두 검사 상태, 다음 행동이 한 카드에 있다. 검사 진입 시 다른 메뉴가 줄고 담당 권한으로 검사 종류를 제한한다. 검사 확인과 최종 승인을 분리한다.
문제 A: 기본 판정이 합격이다. FieldConfirmation의 result 초기값은 pass이고 팩 상세 검사 폼도 첫 선택이 pass다. 사용자가 판정을 명시적으로 선택하지 않아도 메모 단계와 저장으로 진행할 수 있다. 현재 UI는 미판단과 합격을 구별하지 못한다.
권고: 최초에는 미판정 상태로 두고 합격/불합격을 직접 선택해야 저장 가능하게 한다. 단순히 확인 팝업을 하나 더 붙이는 방식은 피한다.
문제 B: 실운영 화면도 시험 검사가 기본이다. 잘못된 실측 집계를 막는 취지는 유지해야 한다. 그러나 반복 작업자가 검사 근거 구분을 잊으면 실제 검사 기록을 시험으로 남겨 집계에서 놓칠 수 있다.
권고: 운영/시험 작업 문맥을 시작 시 명확히 선택·고정하고 매 저장 화면에 유지한다. 합성 체험은 시험으로 강제한다. 실제 근거 없이 실측으로 자동 변환하지 않는다.
문제 C: 현장 전용 2단계 검사와 팩 상세 모달의 검사 폼이 별개다. 같은 기록 업무의 배치·기본 선택·이력 확인 방식이 달라 경로마다 사용법을 익혀야 한다.
권고: 진입점은 유지하되 기록 편집기는 하나로 통일한다. 팩 상세는 이력 중심, 기록은 동일한 검사 작업 화면으로 연결한다.
문제 D: 현장 판단 화면은 이전/다음 대상 중심이며 팩 직접 검색·스캔 진입이 없다. 팩이 많아졌을 때 실제 손에 든 팩과 화면의 우선순위 팩을 맞추기 어려울 위험이 있다. 대량 작업 실측 결과는 아니다.
권고: 현재 팩 식별과 담당 공정 확인을 우선하고 직접 찾기 경로를 둔다. 저장 후 자동으로 다른 팩을 선택해 오기록을 유발하지 않는다.

4. 셀 매칭 담당자의 사고 흐름
질문: 어떤 셀을 대상으로 했고, 후보 간 차이는 무엇이며, 어느 후보를 어떤 근거로 확정할지 알고 싶다.
관찰: 파일 등록 후 하단 메뉴로 매칭에 진입하면 이전 '측정 데이터 준비 완료/조합 비교로 이어가기' 배너가 남는다. 이미 조합 결과를 보고 있는데 이전 단계 이동이 주요 버튼으로 남아 있다.
관찰: SOP 설명, 완료 배너, 실행 결과 안내, 한계 설명, 후보 선택 칩이 세로로 쌓인다. 이 경로에서 후보 본문 영역 높이는 PC 약 138px, 모바일 약 53px였다. 내부 내용 높이는 각각 약 293px/287px로 내부 스크롤이 필요했다. 모든 경로에서 동일한 높이라는 뜻은 아니다.
관찰: 첫 후보의 칩 이름은 '8셀 추천 조합 2'인데 본문은 RECOMMENDATION 01이다. TaskSteps가 패널 배열의 위치를 붙여 후보 번호와 섞인다. 기능 동작과 별개로 후보 식별이 모호하다.
권고: 대상 LOT·사용 셀 수·기준 버전은 작은 고정 요약으로, 실제 후보 차이와 확정 행동은 주요 영역으로 배치한다. 완료 안내는 다음 업무 진입 시 종료한다. 후보 A/B/C 또는 후보 1/2/3을 실제 조합 번호와 일치시킨다. 조건 설정과 후보 비교는 목적에 따른 두 화면으로 구성한다.

5. 관제 승인권자의 사고 흐름
질문: 승인 대기 중 무엇이 급한지, 최신 두 검사가 유효한지, 재검사/결측/변경 사항이 있는지, 누구의 근거로 승인할지 알고 싶다.
좋은 점: 독립 승인, 제출 당시 근거, 재검사 후 승인 재검토, 반려 의견이 있다. 이 안전한 업무 규칙은 보존해야 한다.
관찰: 체험 역할 전환을 제외한 실제 권한 형태의 화면에서도 PC 1366×768에서 검토 본문 높이 367px에 내용 896px가 들어갔다. 최초 스크롤 위치에서 승인 버튼의 상단은 약 y=990px였다. 모바일 390×844에서는 본문 454px/내용 1044px, 버튼 상단 약 y=1128px였다.
의미: 가로 넘침은 없어도 근거를 읽고 의견을 입력하고 승인하려면 내부 스크롤이 발생한다. 승인 시 앞에서 본 팩과 검사 요약을 기억해야 한다. 특히 현재 상단에는 공통 메뉴·복귀·새로고침·목록 복귀가 남아 있다.
권고: 팩/제출본/출처/검사 상태를 상시 보이는 요약으로 고정한다. PC는 대기목록·판단 근거·의견/행동을 연결하고, 작은 화면은 '요약/검사 근거/판단'을 명확한 탭으로 전환한다. 최종 승인·반려는 보이는 위치에 두되 근거 부족과 권한 제한을 그대로 적용한다. 모든 근거를 첫 화면에 펼치지는 않는다.
주의: 상단 작업대의 실측/시험 집계 문맥과 개별 승인 제출본의 자료 출처가 다를 수 있다. 양쪽이 서로 다른 범위임을 명시해 집계 필터를 현재 승인 자료의 성격으로 오해하지 않게 해야 한다.

6. 관제 지표와 의사결정
관찰: 불량률은 분석·보고, 연결률은 데이터 인입, 공정별 대기는 공정 공간으로 나뉜다. 최신/초도 지표도 서로 전환해서 읽는다. 각각은 단순하지만 업무 상태를 종합하려면 사람이 값과 집계 조건을 기억해야 한다.
관찰: '초도·판단 근거'에 보고서·비교 근거·알고리즘 검증이 함께 있다. 보고서를 원하는 사용자가 초도라는 메뉴를 먼저 떠올려야 한다. 이름이 목적지의 기능 범위를 충분히 표현하지 못한다.
권고: 관제 시작 화면에 불량률→검사 연결→공정별 대기→처리량의 작은 판단 요약을 한 집계 기준으로 제공한다. 해당 이상을 선택하면 같은 범위와 대상 팩을 유지해 처리한다. 연구 도구는 일상 품질 승인과 다른 업무 묶음으로 둔다. 카드 수를 늘려 기존 페이지 내용을 그대로 복제하지 않는다.

7. 가상 공정 설계·연구 담당자
좋은 점: 가상 공간과 실제 장비 미연결을 구분하고 명시적으로 실행해야 시뮬레이션이 시작된다. 이 원칙은 유지한다.
관찰: 공정 설계에는 설비 상태/구성/시뮬레이션, 장비 추가/목록/설정/연결/저장/검토, 장비 설정 내부 탭이 중첩된다. 스크롤을 없애도 사용자가 현재 도구의 단계를 기억해야 한다.
권고: 선택 장비와 그 장비에 필요한 속성/연결/검증을 가까이 배치하고, 장비 선택 시 해당 작업을 직접 드러낸다. 설계·실행·결과 검토는 분명히 구분하되 일반 품질 업무 메뉴와 경쟁시키지 않는다.
관찰: 연구 화면에는 단계 1/2/4와 별도 검증/추론/이력 도구가 같은 줄에 있다. 결과가 생성돼야 나타나는 단계와 항상 쓰는 도구가 섞인다.
권고: '조합 비교 / 데이터 준비 검증 / 연구 모델 체험'의 목적을 먼저 나누고, 선택한 목적 안에서 입력→조건→결과 순서를 유지한다. 실무 승인에 연구 결과가 자동 반영된다는 인상을 주지 않는다.

8. 공통 인지 부담
- 선택된 모드·탭·선택 칩과 실제 실행 버튼이 모두 유사한 녹색 강조다. 현재 위치와 다음 행동의 시각적 역할을 구분할 필요가 있다. 색을 더 늘리기보다는 채움/테두리/위치/문구로 구분한다.
- 탭과 칩을 모두 바깥으로 드러내는 것은 발견에는 유리하지만, 동등한 중요도로 펼치면 판단을 도울 본문이 줄어든다. 드롭다운 복귀가 아니라 현재 업무별 선택지의 범위를 조정해야 한다.
- '판단 화면으로', '승인 목록으로', '품질 결과 확인', '비교 근거 확인' 등 복귀와 이동의 목적이 다르다. 사용자가 돌아갈 대상/유지되는 팩을 알 수 있게 표현한다.
- 단순 현장 화면은 큰 여백과 작은 핵심 텍스트가 공존한다. 여백을 추가 정보로 채우기보다 팩 식별·현재 검사·다음 행동의 가독성을 높인다.
- 화면 안내의 정확한 하이라이트는 도움이 되지만, 현재 없는 업무 항목까지 선택해 '보이지 않음'을 읽는 것은 추가 탐색이다. 현재 단계 도움말과 전체 DOCS의 역할을 분리한다.
- DOCS는 교육·참고 자료다. 반복 업무마다 DOCS를 열어야 한다면 업무 화면을 개선해야 한다.

9. 개선 우선순위 및 완료 기준 제안
P0: 합격 기본 선택 제거, 운영/시험 문맥 명확화. 완료 기준은 판정 미선택 저장 불가 및 현재 기록의 근거 종류 상시 확인이다.
P1: 후보 본문을 가리는 완료 안내와 다단 상단 영역 정리, 후보 번호 일치. 완료 기준은 후보의 핵심 편차와 확정 행동을 같은 화면에서 비교 가능하게 하는 것이다.
P1: 승인 요약과 의견/행동을 분리된 스크롤 영역 사이에서 잃지 않게 구성. 완료 기준은 승인 직전 현재 팩·검사 상태·출처를 다시 볼 수 있는 것이다.
P1: 동일 검사 입력 흐름 통합, 현장 대상 식별 경로 보완. 자동 다음 팩 선택은 피한다.
P1: 관제의 주요 네 지표와 이상 처리 대상 연결. 집계 범위와 조회 시각을 유지한다.
P2: 모드/탭/실행의 시각적 계층, 작업 중심 명칭, 연구·설계 도구 구분, 현재 단계 안내 정리.

10. 보존할 것과 다음 검증
역할 분리, 원본/보완/시험 표시, 동일 팩 연계, 독립 승인, 재검사 이력, 자료 최신성 안내, 명시적 모의 실행을 보존한다.
