업무 구조와 변경 규칙 — 실증 준비형 MVP

기준 버전: 237ced6. 화면 구성과 업무 결과, 기존 DB·승인 이력은 보존한다.

1. 경계
App: 인증과 계정별 작업 공간 수명만 소유한다.
Workbench: 현장/관제 내 화면 연결과 사용자 선택을 소유한다.
application: 조회 수명, 업무 명령, 보고서 생성을 소유한다.
data: Supabase 접근과 응답 검증을 소유한다. 화면에 쿼리를 확산하지 않는다.
domain/shared: 계산 규칙과 SOP 계약. UI·인증·네트워크에 의존하지 않는다.
DB: 권한, 상태 전이, 중복 사용 방지, 독립 승인, 고정 증빙의 최종 권한자.

2. 데이터 소유권
원자료: intake_batches.original_rows, 수정하지 않는다.
검토 중 측정값: intake_batches.rows와 revision. 검토 RPC만 변경한다.
현재 재고: cells. 검토 RPC가 동기화하며 사용한 셀은 변경하지 않는다.
추천 근거: matching_runs. 계산 당시 입력과 버전을 고정한다.
품질 제출본: quality_requests.snapshot. 이후 재검사는 새 검토를 요구한다.
가상 설계: 개인 초안과 승인 제출본을 구분. 현장 장비 상태로 취급하지 않는다.

3. 상태 수명
인증 계정 또는 체험 모드가 바뀌면 작업 공간을 폐기하고 새로 만든다.
해제된 작업 공간의 비동기 응답은 새로운 계정의 상태에 적용할 수 없다.
갱신 중복 실행을 막고 실패 시 마지막 성공 조회본과 실패 표시를 함께 유지한다.
권한 정지시 기존 데이터를 화면에서 제거한다. 서버 권한 검사는 항상 별도 적용한다.
체험 자료는 계정의 운영 데이터와 저장소를 공유하지 않는다.

4. 변경·검증
변경은 인증 경계 → 데이터 접근/조회 → 업무 명령 → 화면 책임 순으로 수행한다.
SOP 변경은 공통 계산 계약과 SQL 최종 검증의 일치 시험을 함께 변경한다.
환경 주소는 배포 설정으로 분리한다. 공개 키만 웹에 포함하며 비밀키는 금지한다.
단위·DB·브라우저·실제 백엔드 시험 후 배포한다. 기능과 데이터 모델 변경을 구조 정리와 혼합하지 않는다.
서버 집계·대규모 증분 조회 및 전체 Supabase Docker 복원은 별도의 검증을 요구한다.

5. 구현 대응
App.tsx/Auth.tsx: 인증 진입, 계정 키 기반 Workbench 교체.
Workbench.tsx: 화면 조립, 선택·탐색과 기능 모듈 연결. 직접 Supabase 호출 금지.
application/useRecords.ts: 취소 가능한 조회, 이전 응답 폐기, 갱신 중복 제어.
application/useProductionWorkflow.ts: 등록·추천·팩 구성·검사 명령과 체험 상태 전이.
application/productionCommands.ts → data/workbenchRepository.ts: 타입이 있는 업무 명령 및 네트워크 접근.
application/qualityReport.ts: 동일 지표 범위의 보고서 출력.
functions/_shared/sop.ts / DB sop_v1(): 불변 SOP 계약. DB 시험으로 값 일치 확인.
read_workbench(): 한 SQL 호출의 동일 MVCC 스냅샷. 구성원만 업무자료 접근, 회원 목록은 관리자만 반환.
workspace_revision: 업무 변경 시 트랜잭션 안에서 갱신. 변경 없는 폴링은 profile/revision만 반환.
신규 사용자·로그아웃·체험 전환 시 스냅샷 버전과 화면 상태를 재사용하지 않는다.
업무 처리 직전 진행 중인 조회가 있으면 명령 완료 후 추가 갱신하여 변경을 놓치지 않는다.
environment.ts / runtime-config.js: 공개 배포 설정. GitHub Pages 기존 기본값 보존, 별도 서버에서 덮어쓰기 가능.

6. 명시적 한계
최초 조회와 데이터 변경 후 조회는 전체 업무 스냅샷이다. 대량 이력의 서버 집계·기간 조회 완료로 표현하지 않는다.
화면별 고객 자료·승인·연구·트윈 모듈은 기존 기능 단위로 유지한다. 이번 책임 분리는 최상위 인증/업무 조정 계층에 적용한다.
전체 Supabase를 Linux Docker로 복원한 결과는 아직 없다. 환경 설정 분리만으로 이관 완료가 되지 않는다.
원본 기록·과거 승인 제출본을 수정하거나 삭제하는 마이그레이션은 포함하지 않는다.
