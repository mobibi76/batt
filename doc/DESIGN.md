# JSI 디자인 규칙

이 규칙은 batt 제품의 모든 화면에 적용한다. 다른 제품의 디자인 시스템과 공유하지 않는다.

제품의 목적은 **데이터 기반 셀 매칭·예측 품질관리로 배터리 팩 불량을 줄이는 것**이다. 제안서의 추정 불량률 2.08% → 목표 1.0%, 대상 공정데이터 100% 연결·표준화를 설계 기준으로 삼는다. 현재 팩 단위 검사 연결률은 학습 데이터 적합성 검증 완료율과 동일하지 않다. 장비 배치, 공정 승인, 계정 관리는 목적을 지원하는 기능이다.

사이드 메뉴는 유지한다. 운영 현황의 첫 순서는 품질 성과·검사 추적성 → 담당자가 확인할 품질 판단 → 공정 대기 → 상세 처리량이다. 품질 판단 작업대는 관측된 불합격, 누락 근거, 독립 검토를 우선순위에 따라 최대 3건만 노출하며, 학습된 위험 예측처럼 표시하지 않는다. 승인 상태 조회 실패는 0건이나 승인 완료로 치환하지 않는다.

| 화면 | 품질 목적에서의 역할 | 다음 연결 |
| --- | --- | --- |
| 셀 데이터 | 항목·단위·식별정보를 검증한 입력 준비 | 등록 후 셀 매칭 |
| 셀 매칭 | SOP 적합 후보의 편차와 근거 비교 | 확정한 동일 팩의 검사 |
| 팩·검사이력 | 셀 조합과 실제 결과 연결, 불합격·누락 조치 | 해당 팩 제출 또는 기존 제출본 |
| 품질·공정 승인함 | 확인 근거와 사람의 최종 판단 보존 | 현재 팩의 조치 또는 품질 결과 |
| 품질 리포트 | 초도·최신 검사 결과를 분리하여 개선 근거 확인 | 불합격/미연결 대상 또는 알고리즘 검증 |
| 알고리즘 검증 | 공개 데이터에서 후보 방법 비교, 운영 전 검증 | 품질 결과로 복귀; 자동 운영 반영 없음 |
| 가상 디지털 트윈 | 공정 구조·태그 정의와 별도 모의 검증 | 설계 제출본 검토; 실측 없는 품질 판단 금지 |
| 사용자 관리 | 담당 공정·최종 승인 권한 배정 | 권한에 맞는 품질 판단 작업 |

제안서는 SOP를 통과한 조합들 사이에서 실제 후속 품질을 예측하는 학습을 요구한다. 현재 운영 엔진은 SOP·편차 기반이며 공개 데이터 실험도 현장 불량률 검증을 대체하지 않는다. 현장 연결 데이터, 독립 LOT 검증, 예측 QC·수명 모델과 검토 피드백을 통한 모델 개선은 별도 개발·검증이 필요한 범위로 유지한다. 최신 불량률의 감소를 자동으로 알고리즘의 인과적 개선 성과로 보고하지 않는다.

시스템 관리자, 세 공정의 확인 담당, 최종 품질 승인권자를 구분한다. ‘조합 확정’과 ‘최종 품질 승인’은 서로 다른 행위이며 화면 용어도 구분한다. 권한 설정은 사용자 관리의 펼침 영역에 모으고 승인 판단 요약에는 공정별 확인자·결과만 간결하게 표시한다. 상세 ID와 시각·측정값은 근거 영역에서 조회한다.

기능 수가 늘어도 기본 화면의 정보량을 함께 늘리지 않는다. 품질 판단 기준, 이탈·누락, 사람이 결정할 사항을 먼저 보여주고 상세 측정값·설정·처리 이력은 요청 시 펼친다. 요약에도 분모와 데이터 부재를 표시하며, 판단에 필요한 근거를 삭제하지 않는다.

운영 현황은 핵심 품질 지표와 공정 대기를 유지하고 누적 처리량·측정 데이터는 접어둔다. 승인함은 규칙 기반 기준 검사와 사람의 의견 입력을 상세 제출본보다 앞에 둔다. 검토자는 기준을 충족한 제출본도 근거를 남겨 반려할 수 있다. 자동 학습이나 AI 추론이 구현되지 않은 곳에 에이전트 판단을 표시하지 않는다. 기존 제출본·결정 이유·검토자·시각 이력은 향후 평가와 학습을 위한 근거이며, 자동 재학습을 의미하지 않는다.

디지털 트윈의 기본 관제는 실제 장비 미연결과 판단 보류를 표시한다. 공정 구성·시뮬레이션을 명시적으로 구분하고, 구성이나 승인으로 모의 실행을 시작하지 않는다. 시뮬레이션에서 다른 작업으로 전환하면 일시정지한다. 합성 센서·경보·처리량은 시뮬레이션에서만 보인다.

- `src/design-tokens.css`: 공통 색상, 글꼴, 간격, 모서리, 그림자, 컨트롤·아이콘 크기의 단일 정의.
- `src/styles.css`: 공통 버튼·입력·배지·카드·표·모달과 화면별 클래스, 반응형 규칙. 고정 상태는 `done`, `waiting`, `disabled` 같은 클래스로 표현한다.
- JSX에 고정 `style` 객체를 추가하지 않는다. 실행 중 계산한 값이 필요할 때만 CSS 사용자 속성으로 전달한다.
- 가까운 중립 색조는 공통 팔레트를 사용한다. 인증 화면의 배터리 그림, 내비게이션 장식, 오버레이처럼 의미가 다른 색은 이름을 가진 전용 토큰을 유지한다.
- 기존 크기·간격을 보존한 토큰 스케일이다. 새 값을 만들기 전에 같은 역할의 기존 값을 확인한다. 미사용 토큰과 같은 용도의 중복 정의를 남기지 않는다.
- Recharts의 자동 계산 위치·크기, Tooltip 기본 테마는 라이브러리에 맡긴다. 제품에서 지정하는 차트 색상, 축 글꼴, 그라데이션 투명도는 제품 토큰을 사용한다. 데이터 범위·차트 여백 등 라이브러리 구성 API는 유지한다.
- 표와 공정도는 내부 가로 스크롤을 유지한다. 모바일 패널 제목·검색창·액션은 필요한 경우 줄바꿈한다.

범위: 로그인, 가입 신청, 승인 대기·반려·이용 중지, 운영 현황과 공정도, 셀 데이터와 업로드·오류 미리보기, 매칭 조건·추천·승인, 팩·검사이력과 검사 입력, 품질 리포트, 알고리즘 검증의 데이터·조건·결과·이력, 사용자 관리, 공통 알림·빈 상태.

검증: `npm test`, `npm run build`, `npm run test:e2e`. Chrome 레이아웃 회귀 검사는 1440/900/768/390/320px, 높이 720px에서 모든 메뉴, 업로드 버튼 정렬, 검색창 높이, 하단 계정 영역의 접근성을 확인한다. 역할별 접근은 임시 Supabase 계정으로 관리자·작업자·조회자 및 미승인 상태를 확인하며 검사 후 계정을 삭제한다.

공통 패널의 제목·본문·결과는 `--panel-padding-inline`으로 좌우 기준선을 맞춘다. 사이드바와 본문 시작 위치는 같은 너비 토큰을 사용한다. 메뉴가 높이를 초과하면 메뉴 내부를 스크롤하고 계정 영역은 유지한다. 좁은 화면의 상단 액션은 줄바꿈하며 검색 입력에는 일반 폼의 상단 여백을 적용하지 않는다.

가상 디지털 트윈도 같은 제품 토큰을 사용한다. `src/twin.css`는 블록 라이브러리·3D 뷰포트·센서 정의·관제 목록의 컴포넌트 스타일을 제공한다. Three.js 장비의 기하 치수는 개념 공간 단위이며 CSS 레이아웃 값과 분리한다. 3D 색상은 제품 토큰을 읽고 캔버스 크기·카메라 위치·메시 좌표는 렌더러가 계산한다. 라이브러리가 생성하는 캔버스 크기 인라인 스타일을 제품 JSX 인라인 스타일로 취급하지 않는다. WebGL 미지원 시 목록·좌표 입력 기능을 유지한다.

품질·공정 승인함, 제출 폼, 읽기 전용 검사/3D 제출본, 검토 의견과 처리 이력은 `src/approvals.css`에서 같은 제품 토큰을 참조한다. 상태는 클래스와 텍스트로 함께 구분한다. 상태·대상 필터와 상세 표는 작은 화면에서 줄바꿈/내부 스크롤하며, 제출자·승인자·조회자별 동작을 보존한다.

운영 현황의 정보 우선순위는 불량률 → 검사 이력 연결률 → 공정별 대기량(공정도 포함) → 누적 처리량이다. 불량률은 최신 최종검사 기준이며 초도 불량률과 구분한다. 연결률은 합격 여부와 별개인 기록 완전성을 뜻한다. 에이징 기록 대기는 에이징 기록이 없는 팩, 최종검사 기록 대기는 에이징 기록이 있고 최종검사가 없는 팩이다. 미승인 추천 조합은 현재 실행 결과로만 집계하고 단위가 다른 팩 수와 합산하지 않는다. 처리량은 전체 등록 기간의 누적값으로 표시한다.

현장 의사결정 기준: 메뉴는 현장 판단(운영 현황·매칭·검사·승인·측정 데이터), 품질 개선·검증, 운영 관리로 구분한다. 담당 범위의 예외와 판단 근거를 먼저 보여주며 상세 기록은 같은 팩에서 이어간다. 운영 화면은 등록 기록을 15초 간격과 화면 복귀 시 조회한다. 갱신 중·마지막 성공 조회·실패한 이전 조회본을 구분하며 장비 실시간 관제로 표현하지 않는다. 실제 장비 이벤트 수집과 생산 규모에 맞춘 증분 조회는 별도 통합 범위이다.

현장 의사결정 최적화(현재 기준): 상시 메뉴는 운영 현황 / 셀 매칭 / 팩·검사이력 / 품질·공정 승인함 / 품질 분석 / 공정 관리의 6개다. 관리자 설정은 하단에 별도로 제공한다. 셀 데이터는 셀 매칭의 준비 단계, 알고리즘 검증은 품질 분석의 하위 업무다. 조직 카드·SOP 홍보 카드는 사이드바에서 제거한다. 앞서 기록한 3개 메뉴 그룹 방식은 이 구조로 대체한다.

첫 화면은 불량률·이력 연결률, 담당자 우선 판단 최대 3건, 공정 대기만 기본 노출한다. 전체 공정도와 누적 처리량은 펼쳐서 확인한다. 원시 측정값 분포는 셀 데이터에서 확인한다. 의사결정 정보는 대상 → 관측 근거 → 다음 행동으로 연결하고 데이터 없음·갱신 실패를 정상으로 간주하지 않는다. 상세 센서·통계·설계 정보를 첫 화면에 나열하지 않는다.

디지털 트윈 확장 기준(미구현 범위 포함): 현재 개인 설계본과 합성 시뮬레이션을 실제 공장으로 간주하지 않는다. 운영 현황 → 공정도 → 트윈 관제 → 팩·검사 근거 경로는 제공한다. 실제 장비 연결 이후에만 공정·장비·팩 ID의 명시적 매핑을 통해 특정 이상 위치로 이동한다. 현장 배포본은 개인 설계본과 분리하고 승인된 배치 버전을 사용해야 한다. 실제 수집 계약에는 장비 ID, 공정 ID, 팩/LOT 연결, 태그·단위, 측정 시각, 수신 시각, 품질 상태, 순번/중복 방지 ID가 필요하다. 통신 지연·단절·불확실 값은 정상으로 판정하지 않는다. 경보 확인과 원인 해소, 공정 확인과 최종 품질 승인을 분리한다. 에이전트 추천에는 관측 근거·적용 기준·모델 버전을 연결하고 인간의 반려·재검사 결과를 다음 검증 데이터로 남긴다. 교대·당일 지표, OEE, 예측 위험은 필요한 시간/가동/불량 정의와 검증 데이터가 확보되기 전에는 생성하지 않는다. 이 항목들은 실제 장비 통합의 설계 기준이며 이번 변경에서 실측 수집이나 설비 제어를 구현했다는 의미가 아니다.

근거: NIST Digital Twins for Advanced Manufacturing (https://www.nist.gov/programs-projects/digital-twins-advanced-manufacturing), OPC UA Part 4 common parameter types (https://reference.opcfoundation.org/specs/OPC-10000-4/7). 데이터·모델·결과 검증과 측정 시각/품질 상태를 설계 기준으로 참고하며 표준 인증을 주장하지 않는다.

통합 작업대: 로그인 후 기본 진입점은 현장/관제 모드의 고정 뷰포트 작업대다. 공정 공간을 첫 화면으로 사용하되 개인 가상 배치임을 표시한다. 현장에서는 기록상 공정 선택 → 담당 대상 수동 선택 → 검사 판정 → 메모·저장을 같은 영역에서 처리한다. 입력 중 모드·작업 전환은 비활성화하고 입력을 유지한다. 관제에서는 전체 공정 / 독립 최종 품질 / 데이터 인입 / 분석·보고 / 공정 개선을 같은 영역에 교체 표시한다. 모드 선택은 권한 부여가 아니며 기존 RPC·RLS 및 독립 승인 조건을 그대로 적용한다. 관리자·승인권자는 관제, 나머지 구성원은 현장 모드에서 시작한다.

작업대의 대상 ID는 사용자가 선택한다. 자동 갱신이 순서를 바꾸어도 다른 팩으로 자동 이동하지 않으며, 현재 조건에서 벗어난 대상은 상태 변경으로 안내한다. 상세 업무에서 복귀하면 작업대 선택 상태를 유지한다. 장비 실측값과 팩 매핑이 없는 상태에서는 등록된 검사 집계를 장비 경보 색상에 투영하지 않는다. WebGL 외에 장비 선택 목록을 제공한다. 기존 파일 인입·매칭·승인·연구·설계·보고 화면은 상세 업무로 재사용한다. 무스크롤 적용 범위는 통합 작업대와 현장 검사 확인 단계이며, 기존 상세 관리·설계 화면은 아직 세로 스크롤을 포함한다. 실제 장비 수신·맵핑, 관제 상세 승인 전체의 무스크롤 전환은 후속 범위다.

상세 업무 모드 통합: 별도의 상세 업무 진입 경계를 제거하고 기존 도구를 현장/관제 모드 안에서 연다. 현장은 운영 현황·팩 검사·셀 매칭, 관제는 운영 현황·품질 승인·셀 데이터·팩 이력·품질 분석·공정 관리 순서다. 모드 전환은 모든 도구 상단에 남는다. 셀 데이터·분석·승인·설계·사용자 관리로 직접 진입하면 관제로, 매칭으로 진입하면 현장으로 자동 소속을 맞춘다. 팩 이력은 두 모드의 공통 업무이며 현재 모드를 보존한다. 운영 지표는 관제 내부의 기록 집계 화면이다. 기존 상세 도구의 스크롤을 모두 제거했다는 의미는 아니다.

판단 집중: 승인 대상을 열면 목록과 새 요청 폼을 접고 해당 제출본의 근거·판단·이력만 보여준다. 목록으로 돌아가면 필터와 페이지를 보존한다. 관제 분석 요약은 최신 불량률뿐 아니라 초도 불량률과 분모도 함께 표시하고 재검사 효과와 최초 품질 개선을 구분한다. 트윈 내부 관측 모드는 '설비 상태'로 명명해 업무 모드 '관제'와 혼동하지 않게 한다.
